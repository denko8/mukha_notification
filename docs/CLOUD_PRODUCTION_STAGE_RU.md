# Реальные вложения и Android WorkManager: что включено

Это работающая реализация следующего этапа, **не утверждение об enterprise/SLA-готовности**.
Необходимы flutter analyze/test, тесты на телефоне, PostgreSQL/Docker и security review.

## Вложения

- Подтверждённая облачная заметка → «Прикрепить файл».
- PDF, JPEG, PNG, WebP, до 5 МиБ; до 10 файлов/20 МиБ на заметку и 100 МиБ на загрузивший аккаунт.
- Файл копируется в приватный каталог приложения до записи очереди SQLite.
  Удаление исходника из галереи не меняет уже сохранённую копию.
- В очереди максимум 20 вложений. Копия и UUID не меняются при повторах.
- Сначала синхронизация заметки, затем файлы, затем свежий снимок с метаданными.
- В очереди есть ручная отмена. Если файл загрузился, но ответ потерялся,
  повтор с тем же UUID и байтами возвращает тот же объект, не удваивая размер/версию.
- Файлы на сервере — **PostgreSQL BYTEA**, не публичная папка и не URL без авторизации.
  Это упрощает атомарность и резервное копирование небольшого теста. Для больших объёмов
  потребуется S3-совместимое хранилище, lifecycle, сканирование и отдельная процедура backup.
- Каждый upload/download/delete проверяет текущие права на заметку/семью.
- JSON-запросы ограничены 128 КиБ, binary upload — 5 МиБ фактического тела;
  reverse proxy пропускает до 6 MB, точное ограничение обеспечивает API.
- Сервер определяет тип по сигнатуре, но это **не антивирус и не полная валидация PDF**.
  Для публичного сервиса нужен карантин/AV/content inspection.
- Клиент скачивает только авторизованным запросом, проверяет размер и SHA-256,
  открывает приватную копию через системное приложение. Имя пользователя не используется как путь.
- API удаления отдельного файла реализован (DELETE); интерфейс пока позволяет отменить
  очередь и удалить всю заметку, не отдельный уже загруженный файл.
- Скачанные копии остаются на устройстве; отзыв доступа на сервере не стирает их удалённо.
- Для аудио и произвольных документов загрузка пока запрещена явно.

## WorkManager — не Timer

- Переключатель «Фоновый обмен Android» в облачном разделе.
- Настройка сохраняется, регистрируется периодическая задача Android WorkManager:
  интервал от 15 минут, условие наличия сети, exponential backoff при ошибках.
- Callback — отдельная точка входа, отдельный Dart isolate, с регистрацией плагинов.
- Секрет сессии читается через flutter_secure_storage, не передаётся в task inputData.
- Задача читает SQLite, отправляет заметки и вложения, скачивает снимок, обновляет
  локальные будильники без запросов разрешений из фонового процесса.
- Выход выключает задачу. Перед обработкой повторно проверяются сессия/настройка.
- На 401 задача выключается: нужен повторный вход. Причина/время фонового результата
  сохраняются и показываются в облачном разделе.
- Android сам определяет время запуска: Doze, ограничения vivo и Force stop могут
  откладывать/блокировать работу. 15 минут — не обещание точного расписания.
- Работа после свайпа из recent apps зависит от прошивки. Force stop нельзя обходить;
  пользователь должен снова открыть приложение. Проверить автозапуск/батарею на vivo.
- Отключение фонового обмена не отменяет уже поставленные локальные напоминания.

## Защита очереди

SQLite schema v3: общая межизолятная lease с owner UUID, сроком 120 секунд и heartbeat.
UI и worker берут один глобальный lease, чтобы не обрабатывать разные аккаунты одновременно.

Каждая запись рабочего документа проверяет:
1. Lease принадлежит этому обработчику и не истёк.
2. Ревизия документа совпадает с прочитанной.
3. Изменение документа и ревизии фиксируется одной SQLite-транзакцией.

Старый остановленный worker не может перезаписать новую локальную очередь после
истечения lease. Если его сетевой запрос уже ушёл, серверные UUID/версии/квитанции
обеспечивают безопасное повторение. Heartbeat не заменяет проверки при commit.
При занятости UI предлагает повторить, worker возвращает retry.

Lease использует системное время телефона: ручная смена часов — отдельный пограничный
сценарий для проверки. Это не распределённый консенсус и не exactly-once доставка сети.

## Запуск после обновления

1. Backend: `docker compose up -d --build` (миграция **0004**).
2. VPS: обновление по backend/OPERATIONS_RU.md, включая пересборку и миграцию.
3. Android: flutter pub get → flutter analyze → flutter test.
4. Полностью пересобрать/перезапустить: добавлен нативный WorkManager.
   Hot reload недостаточен. Flutter platform scaffolding в этом репозитории не хранится;
   проверить Android-проект, runtime INTERNET и существующие receivers уведомлений.
5. Войти, создать/синхронизировать текст, прикрепить PDF, синхронизировать и открыть его.
6. Включить фоновый обмен. Создать очередь, свернуть/закрыть интерфейс, дождаться
   запуска WorkManager; проверить время/результат после открытия.
7. Проверить на втором устройстве, на потере сети и при отзыве семейного доступа.

## Что нельзя назвать включённым без внешней настройки

**Удалённый push FCM/RuStore пока не реализован.** Для него необходимы проект провайдера,
Android-конфигурация, регистрация устройства, серверный delivery/outbox и политика
недублирования локальных уведомлений. WorkManager — не замена push и не точный будильник.
Секреты провайдера не присылать в чат; их конфигурируют на сервере через секрет-хранилище.

## Проверки

- Серверные тесты покрывают доступ, отзыв семейных прав, retry upload, изменение
  содержимого при том же ID, тип/размер/количество, удаление blob при удалении заметки.
- Добавлены Dart-тесты lease/CAS/изоляции аккаунтов через sqflite_common_ffi.
- Flutter SDK здесь отсутствует: Dart-тесты и нативная фоновая работа не проверены агентом.
- Синтаксический парсер не заменяет flutter analyze и запуск release-сборки на телефоне.
