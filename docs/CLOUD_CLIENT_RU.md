# Облачный клиент (Android)

## Обновление: семья, локальные напоминания, автообмен в открытом разделе

- После синхронизации загружается список семей. Можно создать семью, вступить по
  одноразовому коду, владельцу — создать приглашение и скопировать его.
- Выбор «Куда сохранять новые заметки»: личные либо конкретная семейная доска.
- Семейные подтверждённые записи можно изменять, удалять, задавать дату/время.
- Кнопка «Напоминание» у подтверждённой записи выбирает будущую локальную дату;
  в запрос уходит UTC. Есть явное удаление даты. Диктовка дат здесь пока не подключена.
- Планирование локальных уведомлений выполняется после локальных изменений/обмена;
  требуется разрешение уведомлений и точных будильников Android. При отказе — сообщение,
  а не ложное подтверждение. Серверный FCM push этим не реализуется.
- ID будильника хранится в SQLite, имеет отдельную отрицательную область;
  выход отменяет будильники аккаунта, открытие другого — отменяет предыдущие.
- Основная лента больше не вызывает cancelAll при перепланировании своих будильников.
- Автообмен включается переключателем, каждые 30 секунд только пока открыт раздел.
  При ошибках интервал увеличивается до 8 минут, на 401 автообмен выключается.
  При уходе Android в фон таймер приостанавливается, при возврате обмен запускается.
  При закрытии раздела таймер удаляется; настройка пока не сохраняется между открытиями.
- Во время текстового редактирования/выбора времени автообмен не выполняется,
  чтобы незаметно не изменить базовую версию редактируемого текста.
- При 404 отправки семейной правки её текст сохраняется в приватном blocked-черновике,
  очередь больше не пытается отправить его без доступа. Его можно скопировать в новую запись.

**Не реализовано на этом шаге:** вложения, системный WorkManager при закрытом приложении,
удалённые push. Для WorkManager нужна межизолятная блокировка очереди/безопасное чтение
сессии и проверка Android-конфигурации. Обычный Timer не заменяет системный планировщик.
Ниже описание предыдущего этапа; обновления выше имеют приоритет.


Вход: **Настройки → Облачное пространство**.
Это отдельное тестовое пространство, не автоматическая миграция основной ленты.
Семейный локальный экран остаётся локальным; прежняя кнопка синхронизации не включается.

## Что реализовано

- Регистрация/вход на собственном FastAPI-сервере (email + пароль от 12 символов).
- Bearer-сессия в flutter_secure_storage, не в JSON настроек, не в SQLite.
- Последний аккаунт восстанавливается при открытии раздела без обязательного запроса сети.
- Кэш/очередь в отдельной SQLite, пространство изолировано по origin + user_id.
- Создание текстовых заметок без сети после первого входа.
- Редактирование/удаление подтверждённых личных облачных заметок.
- Ручная отправка очереди с неизменяемым Idempotency-Key и телом.
- Последовательная обработка операций: конфликт не затирает локальный текст.
- Полный снимок скачивается во временный набор, проверяется и фиксируется в SQLite
  только после завершения всех страниц. На ошибке старый кэш остаётся.
- Конфликт: принять серверную версию либо отправить свою с новым ключом и актуальной версией.
- При удалении на сервере локальный конфликтный текст можно создать как новую заметку.
- Выход убирает защищённую сессию, но не удаляет очередь аккаунта из SQLite.
- Отправка токена на редиректы запрещена. HTTPS обязателен по умолчанию.

## Что пока намеренно ограничено

- Не переносим локальные заметки основной ленты, категории и вложения в аккаунт автоматически.
- Не подключаем глобальный notesNotifier/LocalSyncService к новому хранилищу.
- Системной фоновой синхронизации и автообновления сессии пока нет.
  Есть автообмен открытого раздела с backoff. После 401 требуется выход/повторный вход.
- Пока заметка ждёт подтверждения, её повторное редактирование заблокировано:
  нельзя менять тело операции, которую сервер уже мог выполнить.
- Управление участниками (выход/удаление) пока доступно через API, не через этот экран.
- Облачные даты не парсятся из текста; локальные уведомления ставятся через явный выбор даты.
- Системные напоминания, фотографии/PDF и привычная лента работают по прежней локальной схеме.
- Состояние очереди и кэш — приватная SQLite, но не SQLCipher/E2E-шифрование.
- Кэш прочитанных семейных заметок офлайн может оставаться до успешной проверки сервера.
- Черновик, ещё не сохранённый в SQLite, не гарантированно переживает закрытие экрана/процесса.
- Web/iOS/desktop-клиент облака пока не включён. На неподдерживаемой платформе есть объяснение.

## Как проверить

1. Получить изменения, выполнить `flutter pub get`, `flutter analyze`, `flutter test`.
2. **Полностью остановить и заново запустить приложение**: добавлены нативные плагины
   flutter_secure_storage и sqflite, hot reload недостаточен.
3. Запустить backend с миграцией 0003 по backend/OPERATIONS_RU.md.
4. Ввести HTTPS-адрес своего сервера без `/api`, пути и query-параметров.
5. Создать аккаунт, добавить текст, убедиться в статусе «Ожидает отправки».
6. Синхронизировать, проверить заметку через API или второе устройство.
7. Отключить сеть, создать заметку, закрыть/открыть раздел; включить сеть и отправить.
8. Изменить заметку через API с другого клиента, затем отправить старую локальную
   правку. Должен появиться выбор двух версий, а не молчаливая перезапись.
9. Выйти/войти в тот же аккаунт: очередь должна сохраниться. Другой аккаунт её не видит.

### Локальный сервер без HTTPS — только разработка

Для эмулятора Android адрес хост-компьютера обычно `http://10.0.2.2:8000`,
**не localhost телефона**. Телефон в сети использует LAN-адрес компьютера; Docker
по умолчанию слушает только loopback, не открывайте его наружу без необходимости.

Чтобы явно разрешить HTTP клиентскому коду в отладочной сборке:

```
flutter run --dart-define=ALLOW_INSECURE_BACKEND=true
```

Дополнительно Android может блокировать cleartext: разрешение нужно включать только
в debug manifest/network security config сгенерированного Android-проекта.
Релизную конфигурацию ради этого не ослаблять. Лучше проверить через HTTPS VPS.
HTTP передаёт пароль/сессию незашифрованными — только изолированная тестовая сеть.

### Защищённое хранилище и резервное копирование Android

Сверить настройки flutter_secure_storage с Android-проектом. Не переносить зашифрованные
секреты через обычный Android backup без поддерживаемой схемы восстановления ключей:
это может давать ошибки расшифровки после переустановки/восстановления устройства.
Пароли и токены не публиковать в логах/скриншотах. Удаление приложения может удалить
и неотправленную очередь — это нужно учитывать до ручного теста с важными данными.
